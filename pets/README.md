# 宠物立绘素材（AI 生成，已随包提供）

12 只原创虚构生物，每只 4 个进化阶段 + 公共蛋，共 49 张 webp（约 1.5MB）。

## 目录结构

```
pets/
  _egg.webp            公共蛋形态（Lv0，所有物种共用）
  pyro/1.webp~4.webp   焰灵：Lv1 幼生体 / Lv2 成长期 / Lv3 完全体 / Lv4 究极体
  volt/ ...            雷角
  rocko/ ...           岩铁
  gale/ ...            疾风
  drake/ ...           幼龙
  nox/ ...             暗影
  aqua/ ...            泡灵
  sprout/ ...          芽芽
  frost/ ...           霜晶
  moth/ ...            月蛾
  mush/ ...            菌菇
  stella/ ...          星辉
```

## 命名规则

- `pets/<物种key>/<阶段>.webp`：阶段 1~4（0 表示该物种专属蛋，可选）
- `pets/<物种key>/all.png`：兼容保留的单图模式（一图覆盖 Lv1~Lv4）
- 命中顺序：`<阶段>.png/webp/jpg → all.* → 同物种其它阶段 → emoji 兜底`
  - 最后一层是给"只传了部分阶段"的物种准备的：例如只传了阶段 3，那么看阶段 4 / 2 / 1 时都会用这张图顶上，
    先近后远（Lv4 时顺序为 4→3→2→1），不会开天窗；想让它逐级不一样，把缺的阶段补齐即可

## 想换某只的形象

把新图按上面命名放进去覆盖即可，无需改代码；刷新页面生效
（素材探测有缓存，必要时调用 `clearPetAssetCache()`）。

## Docker 部署时：映射宿主机目录热加图

`docker-compose.yml` 已将仓库根的 `./pets` 目录挂载到容器内 `/app/web/dist/pets`
（注意挂载点是构建产物 `web/dist/pets`，不是 `web/public/pets`——后者只是 Vite 源码目录，构建时拷入 dist）。

- 服务端静态文件是每次请求实时读盘，加图/换图后**刷新页面即可生效**，无需重启容器或重建镜像
- **首次挂载无需手动拷贝**：镜像内置一份出厂素材（`/app/pets-default`），容器启动时自动把挂载目录里**缺失的文件**补进去（绝不覆盖你改过/新增的文件）；`./pets` 建个空目录即可
- 升级镜像后新内置的素材同样会自动补齐到 `./pets`；若浏览器缓存了同名旧图，强刷（Ctrl+F5）即可

## 家长端「宠物管理」页（v1.6+）

家长登录后底部导航 →「宠物」：
- **新建宠物**：填名字和图片目录名（key），保存后直接在卡片上点对应阶段上传图片（蛋/Lv1~Lv4）
- **编辑**：改名、换兜底 emoji、调 5 阶段成长阈值（各阶段累计经验），即时生效
- **删除**：仅限家长自建的物种，且有小孩养着时不可删

物种数据存数据库（`pet_species` 表），名字/阈值改完即生效，无需改代码或重建镜像；
上传的图片落在 `pets/` 资产目录（Docker 下即宿主机 `./pets`），自动持久化。
